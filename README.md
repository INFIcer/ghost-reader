# Ghost Reader（虚影读取器）

**版本 1.1.0** · 适用于 Factorio 2.1（含太空时代）

在原版游戏中，建设无人机（建设机器人）的任务无法通过信号获取，但这对于自动化建设非常重要，本 mod 着重解决此问题。mod 添加一个新实体，它读取所在表面或所在物流网络范围内的虚影数量并输出为电路信号，可使用 GUI 进行详细配置。支持调整筛选模式（建筑|地格|升级|临时物品请求）和数量模式（供给请求|回收请求）。

---

# 面向普通玩家

## 这个 Mod 是做什么的

在原版游戏中建设无人机的任务无法通过信号获取，但这对自动化建设非常重要，该mod着重解决此问题。Ghost Reader 把这些请求汇总成一个清晰的物品清单，并作为电路信号输出，方便你自动化计算缺料、驱动显示面板或物流请求。

它读取四类请求，并分别统计**供给**和**回收**两个方向：

| 类型 | 供给 | 回收（会被拆除/回收） |
| ---- | ---- | ---- |
| 建筑 | 待建的建筑虚影 | 被标记拆除的建筑 |
| 地格 | 待铺的地形虚影 | 被标记拆除的地格 |
| 升级 | 升级后的目标建筑 | 升级替换下的原建筑 |
| 临时物品请求 | 请求送入的物品 | 回收储物格请求（移除物品） |

- **供给** = 建设机器人工作**缺少**的物品。
- **回收** = 会被建设机器人**拆除或回收**的物品。

## 如何解锁

- 研究科技「虚影读取器」（前置科技：**建设机器人**）。

## 如何使用

1. 放置一个「虚影读取器」。
2. 把它用红/绿线接入电路网络。
3. 在读取器上点击打开 GUI 面板，设置检索范围、筛选模式和数量模式。
4. 电路网络里就会出现各物品的信号，信号值按当前数量模式计算。

## GUI 面板说明

标准原版风格窗口（可拖动、右上角关闭）。

- **检索范围模式**
  - `表面`：扫描整个星球表面上的全部请求。
  - `物流网络`：只扫描读取器所在的物流网络（建设区域）内的请求。
- **当前范围**：实时显示当前生效的范围。
  - 表面模式：显示所在地，如 `【新地星】`。
  - 物流网络模式：显示 `【网络#id】`。
- **筛选模式**
  - `全部`：建筑 + 地格 + 升级 + 临时物品请求。
  - `建筑` / `地格` / `升级` / `临时物品请求`：只计对应类别。
- **数量模式**
  - `供给 - 回收`：输出供给减回收的净值（可为负，用于求净缺口）。
  - `仅供给`：只输出供给数量。
  - `仅回收`：只输出回收数量。
- **当前输出信号**：以原版信号图标风格（图标 + 右下角数量）实时列出将要输出的各信号。

## 计算细节（重要）

- **物流网络模式**下，建筑、地格、升级和临时物品请求都按各无人机平台（roboport）的**建设区域**（绿色区域）的**并集**计算。因为只有请求实体（或虚影）的中心点落入建设区域内才能被建设机器人响应，所以判断条件与之保持一致。
- **物流网络模式**下，读取器自身必须位于某个无人机平台的**供应区域**（橙色区域）内，才能被判定为「属于某个物流网络」。
- 移动实体（如：坦克、蜘蛛机甲）上的临时物品请求同样会被计入。
- 若某个容器建筑（如箱子）被标记拆除，它**内部已有的物品**也会全部记为回收，同时其中的临时物品请求会作废（不重复计数）。

# 面向 Mod 开发者

本部分面向希望快速理解该 Mod 结构、进而修改或借鉴的开发人员。

## 结构总览

Mod 由三个运行时/数据文件组成，职责清晰分离：

- **data.lua** —— 声明新实体。基于原版恒压器（constant-combinator）原型复制出一个同名自定义实体，并把它内部的贴图引用重定向到本 Mod 自带的图形资源（不依赖 `__base__`），同时注册对应的物品、配方和科技。
- **data-updates.lua** —— 为读取「临时物品请求」做铺垫。它给原版的 item-request-proxy 原型挂上一个创建效果，使该实体每次被创建时都能向脚本发送一个事件（详见下文「临时物品请求」一节）。
- **control.lua** —— 全部运行时逻辑：范围判定、请求扫描、信号输出、GUI 与事件驱动更新。

## 核心数据流

1. **定义范围**：每个读取器按「表面」或「所在物流网络的建设区域」决定扫描范围。
2. **双向扫描**：在每个建设区域内，分别统计**供给**（送入）和**回收**（拆除/回收）两类计数。
3. **数量合成**：按玩家选定的数量模式（净差值 / 仅供给 / 仅回收）把两套计数合并成最终的单物品信号表。
4. **信号输出**：通过实体的恒压器控制行为，把每个物品信号写进插槽。
5. **GUI 展示**：用标准原版风格窗口展示当前范围、模式选择和实时输出信号。

## 范围判定逻辑

- **表面模式**：扫描整个表面。
- **物流网络模式**：先确认读取器落在某个无人机平台的**供应区域**内以确定它所属的网络，再对该网络内所有平台的**建设区域**做**并集**扫描。跨平台重叠的请求会去重。
- 只有请求实体（或虚影）的**中心点**落入建设区域内才被计入，这与游戏判定「能否被建设机器人响应」的规则一致。

## 双向扫描（供给 / 回收）

扫描时同时维护供给与回收两套计数：

- **供给**来自：建筑虚影、地格虚影、升级的目标建筑、临时物品请求的送入请求。
- **回收**来自：被标记拆除的建筑、被标记拆除的地格、升级替换下的原建筑、临时物品请求的移除请求、以及被拆除容器内部已有的物品。

## 临时物品请求（item-request-proxy）

这是较特殊的一类请求，原版机制不主动暴露其创建，因此 Mod 用事件方式补足：

- 通过 data-updates.lua 的创建效果，让每次临时请求实体出现时都能被脚本感知。
- 脚本据此事件驱动地跟踪它，并在其被拆除/销毁时同步清理，避免全图轮询。
- 临时请求的「供给」读取其请求送入的物品；「回收」读取其移除计划，并以其目标容器内的实际库存作为回收数量。

## 事件驱动更新

Mod 优先采用事件驱动，而非每帧轮询：

- 虚影创建/销毁、升级标记、无人机平台增删、临时请求创建/移除等变化都会触发「需要重扫」的标记。
- 在下一个游戏 tick 统一执行一次重扫与信号刷新，避免浪费。
- 打开的 GUI 面板按固定间隔（每 30 tick）刷新实时数值。
- 多个读取器若处于相同表面/网络/模式，会共享一次扫描结果，避免重复计算。

## 文件结构

```
ghost-reader/
├── info.json            # Mod 元数据（name=ghost-reader, version=1.1.0）
├── data.lua             # 实体/物品/配方/科技 + 贴图重定向
├── data-updates.lua     # 为读取临时物品请求挂创建效果
├── control.lua          # 扫描、双向计数、信号输出、GUI、事件驱动
├── graphics/            # 复制的原版贴图与图标（不引用 __base__）
├── locale/en|zh-CN/     # 本地化
└── thumbnail.png
```
